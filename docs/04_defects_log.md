# 04 · Defects actually found during the build

Only real defects are listed: each was observed (failing test, reproduction or reviewer report),
fixed, and covered by a regression test. "Found by" is honest about who found it: **R-x** = Codex, an
independent AI reviewer acting for Herui (not Herui personally, and not a human reviewer); **D-x** = the
builder's (Claude Code's) own tests and runs.

| ID | Found by | Symptom (reproduction) | Root cause | Fix | Regression test |
|---|---|---|---|---|---|
| R-1 | Codex, independent AI reviewer for Herui (static review of checkpoint) | `allocate_largest_remainder(100, [("A",5000),("A",5000)])` returned a dict that did not sum to 100 | Result dict keyed by rep id silently overwrote a duplicate key's floor | Primitive now rejects duplicate keys (`ValueError`) | `tests/test_money.py::AllocationTests::test_duplicate_keys_rejected` |
| R-2 | Codex, independent AI reviewer for Herui (static review) | Calculate + submit January, import a booking-only January contract, close: close succeeded and froze the new, unreviewed bookings KPI | `result_digest` hashed lines/holds/inputs but not KPIs/controls/totals; the snapshot was built from the fresh recomputation | Digest now binds every frozen field (lines, holds, exclusions, totals, controls, KPIs, accounted events, inputs incl. rep display data); the snapshot is built from the **stored reviewed run**; the stale diff lists changed sections | `tests/test_workflow.py::test_booking_only_import_after_review_is_stale` |
| R-3 | Codex, independent AI reviewer for Herui (static review) | Open month: case created for an unpaid collection; exclude the collection; refresh never touched the case (stale non-zero variance) | `variance_table` iterated only expected ∪ recorded keys | Existing case keys are always revisited; amounts go to zero; status → CLEARED; owner/notes preserved | `tests/test_variance.py::test_excluded_collection_clears_existing_case` |
| D-001 | Own unit test (`test_rejected_amounts`) | `parse_amount("٣")` returned 300 (Arabic-Indic digit accepted as 3.00) | Python regex `\d` and `str.isdigit()` match any Unicode decimal digit | ASCII `[0-9]` in amount/percent/date/period/version patterns | `tests/test_money.py::ParseTests::test_rejected_amounts` |
| D-002 | Own review while fixing D-001 | `is_period("2026-04\n")` was `True` | `re.match` with `$` also matches before a trailing newline | All validators use `fullmatch` | `tests/test_import.py::test_trailing_newline_ids_and_periods_rejected` |

| D-004 | Own control-total test | A `0.00` collection was reported under "rows without parseable amount" | `_amount` discarded the parsed zero when positivity failed | Keep the parsed value; the row is still quarantined (`AMOUNT_NOT_POSITIVE`) | `tests/test_import.py::IdempotencyTests::test_control_totals_reconcile` |
| R-4 | Codex, independent AI reviewer for Herui (executed test on checkpoint fb754e0) | One strict-mode file with `A-REFUND` (refund) and `Z-COLLECT` (its same-day collection) raised `sqlite3.IntegrityError: FOREIGN KEY constraint failed` | Rows were *inserted* in canonical (date, id) order, so the refund was written before its collection | Insert every COLLECTION before any REFUND; evaluation order unchanged (engine re-sorts), provenance unchanged | `tests/test_import.py::SameDayRefundTests` (both row orders × both modes: 2 rows commit, +500 −200 = 300) |
| R-5 | Codex, independent AI reviewer for Herui (executed on checkpoint) | (1) payout row with period `0000-01` raised an uncaught `ValueError` inside the importer; (2) `calculate_period(conn, "0000-01", ...)` succeeded and persisted an invalid period | Period validation was regex-only (year 0000 passes); `period_start` then built `date(0, 1, 1)` | One central validator (`periods_util.is_period` / `require_period`): full-string YYYY-MM, real month, documented years 2000-2099; dates outside that range → `DATE_OUT_OF_RANGE`; every workflow entry point validates before writing; `next_period`/`prev_period` cannot leave the range; DB `CHECK` on period columns as defense in depth | `tests/test_import.py::CalendarRangeTests` (4 tests) |
| D-005 | Own web test (`test_csrf_and_trusted_host`) | A request with an untrusted `Host` header returned HTTP 500 instead of 400 | The 400 error page rendered a template that calls `url_for`, but Flask builds no URL adapter for an untrusted host | Error handlers fall back to a plain-text response when the template cannot render | `tests/test_web.py::WebTests::test_csrf_and_trusted_host` |
