# 04 · Defects actually found during the build

Only real defects are listed: each was observed (failing test, reproduction or reviewer report),
fixed, and covered by a regression test. "Found by" is honest about who found it.

| ID | Found by | Symptom (reproduction) | Root cause | Fix | Regression test |
|---|---|---|---|---|---|
| R-1 | External reviewer (static review of checkpoint) | `allocate_largest_remainder(100, [("A",5000),("A",5000)])` returned a dict that did not sum to 100 | Result dict keyed by rep id silently overwrote a duplicate key's floor | Primitive now rejects duplicate keys (`ValueError`) | `tests/test_money.py::AllocationTests::test_duplicate_keys_rejected` |
| R-2 | External reviewer (static review) | Calculate + submit January, import a booking-only January contract, close: close succeeded and froze the new, unreviewed bookings KPI | `result_digest` hashed lines/holds/inputs but not KPIs/controls/totals; the snapshot was built from the fresh recomputation | Digest now binds every frozen field (lines, holds, exclusions, totals, controls, KPIs, accounted events, inputs incl. rep display data); the snapshot is built from the **stored reviewed run**; the stale diff lists changed sections | `tests/test_workflow.py::test_booking_only_import_after_review_is_stale` |
| R-3 | External reviewer (static review) | Open month: case created for an unpaid collection; exclude the collection; refresh never touched the case (stale non-zero variance) | `variance_table` iterated only expected ∪ recorded keys | Existing case keys are always revisited; amounts go to zero; status → CLEARED; owner/notes preserved | `tests/test_variance.py::test_excluded_collection_clears_existing_case` |
